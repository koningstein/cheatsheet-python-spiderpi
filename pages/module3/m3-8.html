M3.8: Linting (Kwaliteit)

Theorie: De Spellingscontrole voor Code

Probleem: Onze code werkt, maar is het goede code? Hebben we ongebruikte imports? Te lange regels? Verkeerde naamgeving (mijnKlasse i.p.v. MijnKlasse)?

Oplossing: Een Linter (zoals pylint). Dit is een tool die je code leest (zonder het uit te voeren) en functioneert als een strenge, automatische docent die je code een *cijfer* geeft (op 10).

Het controleert op Fouten (Errors), Waarschuwingen (Warnings), en Stijl-Conventies (Conventions).

Python Voorbeeld (Terminal)

pylint is een tool die je installeert en draait vanuit de terminal.

# 1. Installeren (in je venv)
(venv) C:\...> pip install pylint

# 2. Toevoegen aan je 'recept'
(venv) C:\...> pip freeze > requirements.txt

# 3. Analyseren (draai in de hoofdmap, wijs naar je package)
(venv) C:\...> pylint spiderpi_core

# 4. Voorbeeld Output (je krijgt een 'muur van tekst'):
# ************* Module spiderpi_core.servo
# spiderpi_core\servo.py:1:0: C0114: Missing module docstring (missing-module-docstring)
# spiderpi_core\servo.py:10:4: C0103: Attribute name "_id" doesn't conform to snake_case naming style (invalid-name)
# ...
# -------------------------------------
# Your code has been rated at 3.45/10

# 5. De Opdracht:
# Probeer de makkelijke fouten (C0114, W0611 Unused import)
# op te lossen en kijk of je score stijgt.
