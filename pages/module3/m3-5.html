M3.5: Debuggen (Basis)

Theorie: Stoppen met print()

Probleem: Fouten zoeken met print("DEBUG: waarde is", x) is traag, rommelig en je vergeet ze weg te halen.

Oplossing: Een Visuele Debugger. Dit is een tool in je IDE (zoals VS Code of PyCharm) die veel krachtiger is.

De drie belangrijkste functies zijn:

  1. Breakpoints (Rode Stip): Een "Stop!"-bord voor je code. Je klikt links naast de regelnummers om er een te plaatsen. Je code *pauzeert* daar.
  2. Stap-voor-stap Navigatie:
    • Step Over (F10): Voer de huidige regel uit en ga naar de *volgende* regel.
    • Step Into (F11): Als de regel een functie of methode aanroept (bv. Leg(...)), *spring* dan *in* die methode.
  3. Variabelen Inspecteren: Terwijl de code gepauzeerd is, kun je in het "Variables" of "Debug" venster *live* de inhoud van alle variabelen zien (wat zit er in self? Wat is start_id?).

Python Opdracht (Debugger Stappen)

Dit is een opdracht *zonder* nieuwe code. De opdracht is om de debugger te *gebruiken* om de "cascade" van constructors (M1.10) te volgen.

Open je main.py en volg deze stappen:

# In main.py
from spiderpi_core.robot import SpiderPi

# 1. Zet een Breakpoint op de volgende regel:
#    (Klik links van het regelnummer 5)
my_robot = SpiderPi()

# 2. Start de Debugger (F5 in VS Code)
#    De code pauzeert en markeert regel 5 geel.

# 3. Druk op Step Into (F11).
# 4. Je springt nu IN de __init__ van SpiderPi (in robot.py).

# 5. Druk op Step Over (F10) om regel voor regel te gaan.
# 6. Ga naar het 'VARIABLES' / 'VARIABLES' venster om 'self' te inspecteren.
#    Je zult zien dat 'self' langzaam wordt opgebouwd.

# 7. Druk nogmaals Step Into (F11) als je op self._leg_front_r = Leg(...) staat.
# 8. Je springt nu IN de __init__ van Leg (in leg.py).

# 9. Druk nogmaals Step Into (F11) als je op self._hip_servo = Servo(...) staat.
# 10. Je springt nu IN de __init__ van Servo (in servo.py).

print("Debuggen voltooid.")

Door dit te doen *zie* je precies hoe de objecten (SpiderPi, Leg, Servo) in elkaar zitten.
