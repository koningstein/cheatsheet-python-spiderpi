M5.2: Abstracte Methoden

Theorie: Het 'Contract' (Deel 2: De Eis)

Een ABC (Les 5.1) wordt pas krachtig als we het combineren met @abstractmethod.

Dit is een 'decorator' die je boven een methode zet. Het betekent: "Ik (de Ouder) heb geen code voor deze methode, maar ik eis dat elk 'kind' (subklasse) dat deze klasse erft, deze methode zelf implementeert."

Een klasse met één of meer abstracte methoden kan zelf niet meer geïnstantieerd (aangemaakt) worden.

Python Voorbeeld (`actions.py`)

We passen AbstractRobotAction aan en voegen de 'eis' toe.

from abc import ABC, abstractmethod
from spiderpi_core.robot import SpiderPi

class AbstractRobotAction(ABC):
    # ... (init van Les 5.1) ...

    # DIT IS HET CONTRACT:
    @abstractmethod
    def execute(self) -> None:
        """
        Voert de specifieke robot-actie uit.
        Kind-klassen MOETEN dit implementeren.
        """
        pass # Geen code hier

# --- In main.py ---
# from spiderpi_core.actions import AbstractRobotAction
#
# actie = AbstractRobotAction(my_robot)
#
# ^^^ DIT CRASHT NU (TypeError)
# Fout: Can't instantiate abstract class AbstractRobotAction
#       with abstract method execute
# Dit is de "win" van de les! Het contract werkt.
