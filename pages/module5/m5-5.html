M5.5: Abstractie voor Sensoren

Theorie: Een Contract voor Data

Dit is een herhaling van het abstractie-concept (M5.1 & M5.2), maar nu toegepast op een nieuw domein: Sensoren.

Probleem: Een Ultrasoon-sensor geeft *afstand in cm*. Een Temperatuur-sensor geeft *graden Celsius*. Ze lijken verschillend, maar ze doen conceptueel hetzelfde: ze lezen een waarde.

Oplossing: We maken een AbstractSensor contract (ABC) dat *eist* dat elke sensor die we op de robot aansluiten, een .read_value() methode heeft.

Python Voorbeeld (`sensors.py`)

We maken een nieuw bestand spiderpi_core/sensors.py.

# In spiderpi_core/sensors.py
from abc import ABC, abstractmethod

class AbstractSensor(ABC):
    """
    Contract voor alle sensoren.
    Elke sensor MOET een waarde kunnen lezen.
    """

    @abstractmethod
    def read_value(self) -> float:
        """
        Leest de waarde van de sensor.

        Returns:
            float: De gemeten waarde (bv. cm, graden, etc.)
        """
        pass

# --- Concrete implementatie (om te testen) ---
class MockUltrasonicSensor(AbstractSensor):
    """Een neppe sensor voor test-doeleinden."""

    def read_value(self) -> float:
        """Implementeert het contract. Geeft een neppe waarde terug."""
        print("Ultrasoon sensor leest...")
        return 10.5 # Gesimuleerde afstand
