M7.7: Abstracte Sensor Integratie

Theorie: De 'Slimme' Sensor

We hebben twee 'contracten':

  1. AbstractSensor (M5.5) [cite: 249-250]: *Eist* een .read_value() -> float methode (geeft een getal).
  2. VisionProcessorProtocol (M7.1) : *Eist* een .analyze_frame() -> np.ndarray methode (geeft een beeld).

Probleem: Deze lijken onverenigbaar.

Oplossing: We maken een *nieuwe* klasse: VisionSensor. Dit is een "Adapter" klasse.

  • VisionSensor IS EEN AbstractSensor (erft ervan, vervult read_value()).
  • VisionSensor HEEFT EEN Camera (om te kijken).
  • VisionSensor HEEFT EEN ColorDetector (om te analyseren).

De .read_value() methode van de VisionSensor doet dan *zelf* de detectie en *telt* de pixels (herhaling M6.7) [cite: 251-252].

Python Voorbeeld (`sensors.py`)

We maken een 'slimme sensor' die *is een* Sensor, maar *vision* gebruikt.

# In spiderpi_core/sensors.py
from .camera import Camera
from .vision import ColorDetector
import cv2
import numpy as np

# ... (AbstractSensor van M5.5) ...

class ColorVisionSensor(AbstractSensor):
    """
    IS EEN Sensor. HEEFT EEN Camera en Kleur-grenzen.
    Implementeert .read_value() door pixels te tellen.
    """
    _camera: Camera
    _detector: ColorDetector

    def __init__(self, camera: Camera, lower_bound: np.ndarray, upper_bound: np.ndarray):
        self._camera = camera
        # Maak de *specifieke* processor die deze sensor nodig heeft
        self._detector = ColorDetector(lower_bound, upper_bound)

    def read_value(self) -> float:
        """Leest de sensor: telt de gekleurde pixels."""
        frame = self._camera.get_frame()
        if frame is None:
            return 0.0

        # Gebruik de detector om het masker te krijgen
        mask = self._detector.analyze_frame(frame)

        # Tel de pixels (logica uit M6.7)
        count = cv2.countNonZero(mask)
        return float(count)
