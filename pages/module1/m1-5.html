M1.5: Getters (Read-Only)

Theorie: Data Veilig Lezen

Een Getter is een methode die bedoeld is om een property veilig uit te lezen.

Probleem: Onze set_angle (Setter) is nu veilig, maar een gebruiker kan de validatie nog steeds omzeilen door motor.current_angle = 9000 direct in te stellen.

Oplossing: We 'verstoppen' de echte data-property (dit heet **Encapsulatie**) en geven de gebruiker een 'read-only' getter om de waarde te lezen.

  1. We hernoemen de 'echte' data naar self._current_angle (met een underscore _). Dit is de Python-conventie voor "protected": "blijf hier af, dit is intern".
  2. We maken een Getter met @property. Dit is een speciale methode die eruitziet als een property (je roept hem aan zonder haakjes).

Python Voorbeeld

# In servo.py
MIN_ANGLE = 0.0
MAX_ANGLE = 180.0

class Servo:
    # De 'echte' data is nu 'protected' (verstopt)
    _current_angle = 0.0 # We geven een default waarde
    id = 0 # 'id' is nog wel public

    def set_angle(self, new_angle):
        """SETTER: Past de *protected* property aan."""
        if new_angle >= MIN_ANGLE and new_angle <= MAX_ANGLE:
            self._current_angle = new_angle # Past _current_angle aan
            print(f"Motor {self.id} beweegt naar {self._current_angle} gr.")
        else:
            print(f"FOUT: Hoek {new_angle} is ongeldig.")

    # De GETTER
    @property
    def current_angle(self):
        """GETTER: Leest de *protected* property 'read-only' uit."""
        return self._current_angle

# In main.py
motor = Servo()
motor.id = 1
motor.set_angle(90.0)

# 1. Lezen (gebruikt de getter, zonder haakjes)
print(f"Hoek is: {motor.current_angle}") # Output: 90.0

# 2. Schrijven (CRASHT!)
# motor.current_angle = 200.0 # AttributeError: can't set attribute
# Dit is GOED! Onze data is nu veilig.
