M1.4: Setters met Validatie

Leeruitkomsten

  • Ik begrijp het belang van Validatie om de toestand van een object te beschermen.
  • Ik kan if/else logica gebruiken in een methode om data te valideren.
  • Ik begrijp dat een methode die data instelt een Setter wordt genoemd.

Uitleg: Data Beschermen (Setters)

In M1.3 was onze set_angle methode "dom" en accepteerde 9000.0, wat de toestand van ons object corrupt maakte.

De oplossing is om "regels" (validatie) toe te voegen binnen de methode. Een methode die een property instelt en valideert, noemen we een Setter. 

# In servo.py

# Constanten (bovenaan het bestand)
MIN_ANGLE = 0.0
MAX_ANGLE = 180.0

class Servo:
    # ...
    def set_angle(self, new_angle):
        """Stelt de hoek in, MAAR alleen als deze geldig is."""

        # De VALIDATIE-check
        if new_angle >= MIN_ANGLE and new_angle <= MAX_ANGLE:
            self.current_angle = new_angle
            print(f"Motor {self.id} beweegt naar {self.current_angle} gr.")
        else:
            # Weiger de ongeldige waarde
            print(f"FOUT: Hoek {new_angle} is ongeldig.")

Uitleg: De Setter Testen

Als we nu ongeldige data proberen in te stellen via de set_angle methode, wordt deze netjes geweigerd. 

# In main.py
from servo import Servo

motor = Servo()
motor.id = 1
motor.current_angle = 90.0

motor.set_angle(200.0)  # Output: FOUT: Hoek 200.0 is ongeldig.
motor.set_angle(120.0)  # Output: Motor 1 beweegt naar 120.0 gr.

print(f"Uiteindelijke hoek: {motor.current_angle}") # Output: 120.0

Het Nieuwe Probleem...

We hebben de "voordeur" (de methode) beveiligd. Maar wat als iemand de "achterdeur" gebruikt?

motor.current_angle = 9000.0

Dit omzeilt onze setter volledig en maakt de property alsnog kapot. Dit "lek" lossen we in de volgende les op.
