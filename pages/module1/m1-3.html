M1.3: Methoden (Gedrag)

Leeruitkomsten

  • Ik begrijp het concept van een Methode als een functie die "leeft" binnen een klasse.
  • Ik kan een methode definiëren met het def keyword en het verplichte self argument.
  • Ik kan een methode aanroepen op een object-instantie.

Uitleg: Gedrag Toevoegen (Methoden)

Properties (M1.2) definiëren wat een object is (zijn toestand). Methoden definiëren wat een object kan doen (zijn gedrag).

Vergelijking: Een Auto heeft een snelheid (property), maar doet versnellen() (methode).

Een methode is een functie die je binnen een klasse definieert. Het moet altijd self als eerste parameter hebben. self verwijst naar het object zelf, zodat de methode zijn eigen properties kan aanpassen. 

# In servo.py
class Servo:
    """Modelleert een enkele motor (servo)."""

    # Dit is een methode (een functie binnen een klasse)
    def set_angle(self, new_angle):
        """
        Stelt de hoek van deze specifieke servo in.
        'self' verwijst naar het object dat deze methode aanroept.
        """

        # Gebruik 'self' om de property van DIT object aan te passen
        self.current_angle = new_angle

        # We gebruiken 'self.id' (aangemaakt in main.py)
        print(f"Motor {self.id} beweegt nu naar {self.current_angle} graden.")

Uitleg: De Methode Aanroepen

We roepen de methode aan op het object met de punt-notatie. De methode past vervolgens de toestand (de property) van dat specifieke object aan. 

# In main.py
from servo import Servo

motor = Servo()
motor.id = 1
motor.current_angle = 90.0
print(f"Beginhoek: {motor.current_angle}")

# Roep de methode aan op het object
motor.set_angle(110.0)

# De property is nu aangepast
print(f"Nieuwe hoek: {motor.current_angle}")

# Output:
# Beginhoek: 90.0
# Motor 1 beweegt nu naar 110.0 graden.
# Nieuwe hoek: 110.0

Het Probleem...

Wat gebeurt er als je motor.set_angle(9000.0) aanroept? De code accepteert dit, en de toestand van ons object is nu corrupt (9000.0 is geen echte hoek). Dit lossen we in de volgende les op.
