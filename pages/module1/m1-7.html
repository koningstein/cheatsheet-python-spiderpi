M1.7: Named Arguments

Leeruitkomsten

  • Ik begrijp het verschil tussen Positional Arguments (op volgorde) en Named Arguments (op naam).
  • Ik kan objecten instantiëren door de parameter-namen expliciet te noemen.
  • Ik begrijp hoe dit de leesbaarheid van de code verbetert en de volgorde onbelangrijk maakt.

Uitleg: Leesbaarheid en Veiligheid

Tot nu toe gebruikten we Positional Arguments. Python keek puur naar de volgorde:
Servo(1, 90.0) betekent: het eerste getal is het ID, het tweede is de hoek.

Probleem: Als je later de constructor aanpast en de parameters omdraait, crasht al je oude code. Ook is het voor een andere programmeur niet duidelijk wat 1 en 90.0 betekenen zonder de documentatie te lezen.

Oplossing: Met Named Arguments (Benoemde Argumenten) geef je expliciet aan welke waarde bij welke parameter hoort.

Python Voorbeeld

In servo.py (De definitie):

We geven de parameters duidelijke namen.

class Servo:
    def __init__(self, start_id, start_angle):
        # ... (implementatie)

In main.py (Het gebruik):

# OUD (Positional):
# Onduidelijk. Is 1 de hoek of het ID?
motor1 = Servo(1, 90.0)

# NIEUW (Named):
# Glashelder. De volgorde maakt niet meer uit.
motor2 = Servo(start_id=2, start_angle=100.0)
motor3 = Servo(start_angle=110.0, start_id=3)

Voordelen

  • Zelf-documenterend: Je leest direct wat de waarde betekent.
  • Flexibel: Je hoeft de volgorde niet uit je hoofd te leren.
  • Veilig: Als je parameters toevoegt aan de klasse, blijft oude code met named arguments vaak nog werken (zeker in combinatie met default values).
