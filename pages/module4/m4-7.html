M4.7: Polymorfisme

Theorie: Vele Vormen

Polymorfisme (een moeilijk woord voor een simpel idee) betekent "vele vormen".

Dankzij overerving (Servo IS EEN RobotComponent en Leg IS EEN RobotComponent), mogen we ze *allemaal* simpelweg "RobotComponent" noemen.

De Kracht: Je kunt een lijst maken met *gemixte* objecten (Legs en Servos door elkaar) en ze *exact* hetzelfde behandelen. Als je component.reset() aanroept, kiest Python *automatisch* de juiste (overschreven) methode. Dit is de 'magie' en het hoofddoel van overerving.

Python Voorbeeld (`main.py`)

We maken een gemixte lijst en roepen op alles .reset() aan.

# In main.py
my_robot = SpiderPi()

print("--- Componenten aanmaken ---")

# Een 'gemixte' lijst. Beiden ZIJN EEN 'RobotComponent'.
componenten_lijst = [
    my_robot.leg_front_r,       # Dit is een Leg object
    my_robot.leg_mid_l.hip_servo, # Dit is een Servo object
    my_robot.leg_rear_r         # Dit is nog een Leg object
]

print("\n--- START POLYMORFISCHE RESET ---")
for component in componenten_lijst:
    # We weten niet wat 'component' is (Leg? Servo?)
    # ...en het BOEIT NIET! Python kiest de juiste .reset().
    print(f"--- Volgende component: {component.name} ---")
    component.reset()

# Output:
# --- Volgende component: Leg_1_2_3 ---
# LEG RESET: Leg_1_2_3 reset al zijn servo's.
# SERVO RESET: Servo_1 gaat naar 90 graden.
# ...
# --- Volgende component: Servo_13 ---
# SERVO RESET: Servo_13 gaat naar 90 graden.
# --- Volgende component: Leg_7_8_9 ---
# LEG RESET: Leg_7_8_9 reset al zijn servo's.
# ...
