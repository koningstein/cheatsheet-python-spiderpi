M4.8: Protected (Conventie)

Theorie: protected en Overerving

Dit is een herhaling van Les 3.3, maar nu in de context van Overerving.

  • public (geen _): Mag iedereen gebruiken. (Gevaarlijk)
  • protected (één _): Afspraak. Alleen *intern* gebruik, of voor Kind-klassen (subklassen).
  • private (twee __): Technisch geblokkeerd. Zelfs Kind-klassen kunnen er niet bij.

De Regel: Properties die je *wel* wilt afschermen van de buitenwereld, maar *wel* beschikbaar wilt maken voor je Kind-klassen, maak je protected (_).

Python Voorbeeld

We voegen een _config dictionary (protected) toe aan de Ouder, en lezen die uit in het Kind.

In spiderpi_core/component.py (Ouder):

class RobotComponent:
    _name: str
    _config: dict # Nieuwe protected property

    def __init__(self, name: str) -> None:
        self._name = name
        # Protected property in Ouder
        self._config = {"versie": "1.0", "auteur": "Student"}
    # ...

In spiderpi_core/servo.py (Kind):

class Servo(RobotComponent):
    # ... (init, set_angle, etc.)

    def reset(self) -> None:
        """Overschrijft de standaard reset."""

        # Kind-klasse Servo kan de protected property
        # van zijn Ouder (RobotComponent) lezen.
        print(f"SERVO RESET: {self.name} (Config: {self._config['versie']})")

        self.set_angle(90.0)
