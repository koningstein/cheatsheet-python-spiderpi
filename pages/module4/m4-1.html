M4.1: Basis Klasse (Ouderklasse)

Theorie: De "IS EEN" Relatie

Tot nu toe hebben we Compositie (de "Heeft een..." relatie) gebruikt: een SpiderPi heeft Leg objecten .

Nu introduceren we Inheritance (Overerving), de "IS EEN" relatie.

  • Een Servo IS EEN `RobotComponent`.
  • Een Leg IS EEN `RobotComponent`.
  • Vergelijking (Voertuig): Een Sportauto IS EEN Voertuig. Een Vrachtwagen IS EEN Voertuig.

We maken één "Ouder"-klasse (de Basis Class) die alle gedeelde eigenschappen bevat. Voor ons is dit RobotComponent, want alles op de robot is een component en heeft (bijvoorbeeld) een naam.

Python Voorbeeld (Nieuw bestand: `component.py`)

We maken een nieuw bestand spiderpi_core/component.py aan voor de Ouder-klasse.

"""
Bevat de basis-klasse (ouder) voor alle hardware-componenten
op de robot.
"""
class RobotComponent:
    """
    De 'ouder'-klasse voor alle hardware.
    Alle componenten hebben een naam.
    """
    _name: str # Protected property (M3.3)

    def __init__(self, name: str) -> None:
        """Initialiseert de component met een naam."""
        self._name = name
        print(f"Component '{self._name}' wordt geïnitialiseerd...")

    @property
    def name(self) -> str:
        """GETTER: Geeft de (read-only) naam van dit component."""
        return self._name

Testen: Deze les heeft geen main.py test. De "win" is het correct aanmaken van het bestand. We gebruiken het in de volgende les.
