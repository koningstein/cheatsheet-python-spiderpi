M4.1: Basis Klasse (Parent Class)

Uitleg: De "IS EEN" Relatie

Tot nu toe hebben we Compositie gebruikt: een SpiderPi heeft poten. Dit is de "Heeft een..." relatie.

Nu leren we Overerving (Inheritance). Dit is de "IS EEN" relatie.

  • Een Servo IS EEN Robot-Onderdeel.
  • Een Leg IS EEN Robot-Onderdeel.

Vergelijking: Een Sportauto IS EEN Voertuig. Een Vrachtwagen IS EEN Voertuig. Ze zijn verschillend, maar delen eigenschappen van "Voertuig" (zoals wielen en een motor).

Uitleg: De Parent Class Maken

We maken één Parent class (ook wel Basis Class genoemd) die alle gedeelde eigenschappen bevat. Voor onze robot noemen we dit RobotComponent. Alles op de robot is immers een component en heeft bijvoorbeeld een naam. 

# Maak een nieuw bestand: spiderpi_core/component.py

class RobotComponent:
    """
    De Parent class voor alle hardware.
    Alle componenten (Child classes) erven straks van deze klasse.
    """
    _name: str # Protected property (zoals geleerd in M3)

    def __init__(self, name: str) -> None:
        """Initialiseert de component met een naam."""
        self._name = name
        print(f"Component '{self._name}' initialized.")

    @property
    def name(self) -> str:
        """GETTER: Geeft de (read-only) naam van dit component."""
        return self._name

Uitleg: Wat hebben we nu?

We hebben nu een algemene blauwdruk gemaakt. Op zichzelf doet deze klasse nog niet zoveel, maar in de volgende lessen gaan we onze bestaande klassen (Servo, Leg) een Child class maken van deze Parent.
