M2.1: Virtual Environment (venv)

Uitleg: Het Probleem (Ruzie makende software)

Stel je voor dat je Python-software (libraries) op je computer installeert. Project A heeft versie 1.0 van een library nodig, maar Project B heeft versie 2.0 nodig. Ze gaan "ruzie" maken.

Vergelijking (Gereedschap): Zonder venv gooi je al je gereedschap voor al je klussen in één grote, rommelige schuur.

Uitleg: De Oplossing (Je eigen gereedschapskist)

Een Virtual Environment (venv) is een persoonlijke, lege "gereedschapskist" voor alleen jouw project. Alles wat je installeert, komt *alleen* in de venv-map van dit project en stoort andere projecten niet.

Je maakt en activeert een venv met commando's in je terminal. 

# 1. Navigeer in je terminal naar je projectmap
#    (bv. cd C:\MijnDocumenten\SpiderPiProject)

# 2. Maak de venv (je zult een nieuwe map 'venv' zien verschijnen)
python -m venv venv

# 3. Activeer de venv (Windows)
.\venv\Scripts\activate

# (Op Mac/Linux is het: source venv/bin/activate)

Uitleg: Wat is er gebeurd?

Je terminal-prompt (het regeltje waar je typt) verandert nu. Er staat (venv) vooraan. Dit laat zien dat je "speciale gereedschapskist" actief is.

Als je nu software installeert, komt het alleen in deze kist. 

# Je prompt ziet er zo uit:
(venv) C:\MijnDocumenten\SpiderPiProject>

# 4. Nu kun je veilig software installeren
(venv) C:\MijnDocumenten\SpiderPiProject> pip install lewansoul-servo-bus

Uitleg: Het Resultaat

De lewansoul-servo-bus library zit nu *alleen* in de map .\venv\Lib\site-packages\ en nergens anders op je computer. Je project is nu netjes geïsoleerd.
