M2.1: Virtual Environment (venv)

Theorie: Je Eigen Gereedschapskist

Probleem: Je installeert software (libraries) om je robot te besturen (bv. opencv-python). Je installeert deze standaard 'globaal' op je computer. Maar wat als Project A versie 1.0 van een library nodig heeft, en Project B versie 2.0? Ze gaan ruzie maken.

Oplossing: Een Virtual Environment (venv) is een persoonlijke, geïsoleerde 'gereedschapskist' voor alleen jouw project. Alles wat je installeert komt *alleen* in de venv-map van dit project, en stoort andere projecten niet.

  • Vergelijking (Gereedschap): Zonder venv gooi je al je gereedschap (hamers, zagen) voor al je klussen (projecten) in één grote, rommelige schuur (je 'globale' Python-installatie). Een venv is een aparte, schone kist die je pakt voor één specifieke klus.

Python Voorbeeld (Terminal)

venv is een command-line tool. Je gebruikt het in je terminal.

# 1. Navigeer naar je projectmap
cd C:\Projecten\spiderpi_oop

# 2. Maak de venv (er verschijnt een 'venv' map)
python -m venv venv

# 3. Activeer de venv (Windows)
.\venv\Scripts\activate

# (Op Mac/Linux is het: source venv/bin/activate)

# Je terminal-prompt verandert nu naar (venv)...
(venv) C:\Projecten\spiderpi_oop>

# 4. Nu kun je veilig libraries installeren
(venv) C:\Projecten\spiderpi_oop> pip install lewansoul-servo-bus
