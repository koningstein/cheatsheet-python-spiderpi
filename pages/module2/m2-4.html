M2.4: Packages (__init__.py)

Theorie: Van Losse Bladen naar een Boek

Probleem: Onze projectmap is rommelig. main.py is het script dat we *uitvoeren*, maar servo.py, leg.py en robot.py zijn onze *bibliotheek* (onze src code).

Oplossing: Een Package. Een Package is simpelweg een map die modules bevat. Cruciaal: om Python te vertellen dat een map een Package is, moet er een (meestal leeg) bestand in staan genaamd __init__.py.

We maken een map (bv. spiderpi_core) en stoppen onze bibliotheek-bestanden daarin.

Python Voorbeeld (Structuur)

We verplaatsen onze 'module' bestanden naar de 'package' map.

VOOR (Losse Modules):

spiderpi_oop/
├── leg.py
├── main.py
├── robot.py
└── servo.py

NA (Package Structuur):

spiderpi_oop/
├── main.py           <-- Ons 'hoofdscript' (blijft buiten)
└── spiderpi_core/    <-- Ons PACKAGE
    ├── __init__.py   <-- Het 'label' (mag leeg zijn)
    ├── leg.py
    ├── robot.py
    └── servo.py

Let op: Als je dit doet, crasht je main.py! De imports (adresboeken) kloppen niet meer. Dat lossen we in de volgende lessen op.
