M2.6: Hoofdprogramma (Absolute Imports)

Uitleg: Het Probleem (Van buiten naar binnen)

De imports binnen het spiderpi_core package zijn gerepareerd (Les 2.5).

Maar main.py staat buiten het package. Zijn oude import-regel, from robot import SpiderPi, werkt niet meer omdat robot.py nu in een map "verstopt" zit.

Uitleg: De Oplossing (Absoluut Adres)

We moeten een Absolute Import gebruiken. We vertellen main.py het *volledige pad*, beginnend bij de hoofdmap van het project:

"Kijk in de spiderpi_core package (de map), zoek daarin de robot module (het bestand), en importeer daaruit de SpiderPi klasse."

De "formule" voor het adres is: pakketnaam.bestandsnaam 

# In main.py (in de hoofdmap)

# OUD (crasht):
# from robot import SpiderPi

# NIEUW (werkt):
# Volledig pad: Package.Module
from spiderpi_core.robot import SpiderPi

# --- De rest van de code werkt nu weer ---
print("Robot starten...")
my_robot = SpiderPi()
my_robot.wake_up()
print("Klaar.")

Uitleg: Conclusie

Als je nu python main.py draait (met je `venv` actief), werkt het project weer volledig.

We hebben nu een professionele structuur:

  • venv/: Onze geïsoleerde gereedschapskist (M2.1)
  • requirements.txt: De boodschappenlijst (M2.2)
  • spiderpi_core/: Onze bibliotheek als een net Package (M2.4)
  • main.py: Ons hoofdscript dat de bibliotheek gebruikt (M2.6)
