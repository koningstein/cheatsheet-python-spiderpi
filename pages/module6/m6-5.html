M6.5: Videostream CLI

Theorie: De Monitor (`cv2.imshow`)

Probleem: .get_frame() (Les 6.3) haalt *één* foto. Een video is *veel* foto's achter elkaar (bv. 30 per seconde).

Oplossing: We hebben een while True: loop nodig die continu frames ophaalt en toont.

Om een video te tonen, heb je 3 cv2 commando's nodig *binnen* een loop:

  1. frame = ...get_frame(): Haal de foto.
  2. cv2.imshow("Titel", frame): Toon de foto in een venster.
  3. cv2.waitKey(1): Wacht 1 milliseconde op een toetsaanslag. *Dit is cruciaal!* Zonder waitKey ververst het venster niet.

We stoppen deze loop in een nieuwe methode stream() in SpiderPi en koppelen die aan een CLI-commando (herhaling M3.7) [cite: 245-246].

Python Voorbeeld

1. De methode (in robot.py)

# In spiderpi_core/robot.py
import cv2 # Nu ook hier nodig!

class SpiderPi(RobotComponent):
    # ... (init, wave, getters ...)

    def stream(self) -> None:
        """Start een live videostream naar het scherm."""
        if not self._camera:
            print("Kan niet streamen, geen camera gevonden.")
            return

        print("Stream gestart. Druk op 'q' om te stoppen.")
        while True:
            # 1. Haal frame (via delegatie)
            frame = self._camera.get_frame()
            if frame is None:
                break # Stop als frame mislukt

            # 2. Toon frame op scherm
            cv2.imshow("SpiderPi Stream", frame)

            # 3. Wacht 1ms. Stop als 'q' wordt ingedrukt.
            if cv2.waitKey(1) & 0xFF == ord('q'):
                break

        # Opruimen
        cv2.destroyAllWindows()

2. De koppeling (in main.py)

# In main.py
# ... (argparse setup uit M3.6) ...

# In de 'Router'
